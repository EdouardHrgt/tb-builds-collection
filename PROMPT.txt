# Contexte projet : Modded Builds (Vermintide 2, Modded Realm)
Github name: tb-builds-collection https://github.com/EdouardHrgt/tb-builds-collection
## But
Site de partage de builds Vermintide 2 pour le Modded Realm (tourney balance), inspiré de ranalds.gift
(SPA React où le build entier est encodé dans l'URL, ex. /heroes/1/131321/33-1-3-5/...).
Fonctionnalités : créer un compte, se connecter, se déconnecter, créer / éditer /
supprimer / voir un build.
tout le contenu est en ANGLAIS (front & back)

## Stack
- Front : Vue 3 (Composition API, <script setup>), Vite, Vue Router 4, Pinia, CSS simple (pas de lib UI)
- Back : Node (ESM), Express 4, zod (validation), bcryptjs, jsonwebtoken, cookie-parser, express-rate-limit
- BDD : SQLite via better-sqlite3 (SQL brut, pas d'ORM), mode WAL, foreign keys activées
- Auth : JWT dans un cookie httpOnly (sameSite lax, secure en prod, 7 jours), bcrypt (10 rounds),
  rate limit sur /api/auth/* (30 requêtes / 15 min)
- Règles mot de passe : 8 caractères minimum (72 max), au moins 1 chiffre et 1 caractère spécial
- Conventions : UI, messages d'erreur de l'API et commentaires en ANGLAIS. Erreurs API au format
  { error: "message" }. Les erreurs zod renvoient 400 avec le premier message. Formulaires en novalidate
  (validation faite par l'appli pour avoir des messages en anglais).

## Architecture
- Dev : Vite sur :5173 avec proxy /api vers Express sur :3000 (pas de CORS)
- Prod : un seul process Node. Express sert l'API et client/dist (même origine)
- Contrainte hébergement : SQLite = fichier, donc disque PERSISTANT obligatoire
  (VPS ou Fly.io avec volume ; alternative : Turso, en remplaçant better-sqlite3)
- Variables d'env : JWT_SECRET (obligatoire en prod), DB_PATH (défaut ./data/app.db), PORT (défaut 3000)

## Base de données
users  (id, email UNIQUE, username UNIQUE NOCASE, password_hash, created_at)
builds (id, user_id -> users ON DELETE CASCADE, title, description, hero_id, career_id,
        data TEXT/JSON, is_public 0/1, created_at, updated_at)
index : builds(user_id) et builds(is_public, hero_id, career_id)

Forme de builds.data (validée par zod) :
  { talents: [6 entiers 0..3], items: { melee, ranged, necklace, charm, trinket : string } }

## API (préfixe /api)
POST   /auth/register       201, connecte l'utilisateur
POST   /auth/login
POST   /auth/logout         204
GET    /auth/me             401 si non connecté
GET    /builds              public, filtres ?hero= &career= &page= (20 par page)
GET    /me/builds           auth requise (déclaré avant /builds/:id)
GET    /builds/:id          404 si privé et pas l'auteur
POST   /builds              auth requise
PUT    /builds/:id          auteur uniquement (403 sinon)
DELETE /builds/:id          auteur uniquement (403 sinon), 204

Un build renvoyé : { id, title, description, heroId, careerId, data, isPublic,
author, authorId, createdAt, updatedAt }

## Routes front
/  /builds/new (auth)  /builds/:id  /builds/:id/edit (auth)  /me (auth)  /login  /register
